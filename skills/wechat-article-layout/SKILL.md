# wechat-article-layout：文章排版与阅读节奏

同样三千字，排得好是十分钟顺畅读完，排不好是三次划走。本技能只做一件事：**让文章匹配读者的阅读方式**。

## 第一步：判断阅读场景

- **快速扫读**（通勤、信息流）：小标题每 300–500 字一个，段落在 3 行内，关键结论加粗前置。
- **深度阅读**（主动点开、收藏后读）：小标题每 600–800 字一个，段落可稍长，保留论证的呼吸感。
- 不确定时按快速扫读排——公众号默认场景是手机上划。

## 结构整理

1. **骨架**：通读全文，提炼每部分的实际论点，重写成平行结构的小标题（同为步骤、同为问题、同为观点，不混搭）。
2. **段落**：一段一个意思；超过 5 行的段落找断点拆开；相邻两段讲同一件事就合并。
3. **开头三行**：手机首屏只有三行可见——结论或钩子必须在三行内出现，铺垫后置。
4. **收尾**：结尾一段收束，可留一个具体问题引导留言，不写"综上所述"。

## 格式规则

- **加粗**：每屏最多一处，只加粗结论句或关键数字；全加粗等于没加粗。
- **列表**：并列的 3 项以上信息才列表化，2 项保持行文；步骤必须编号。
- **配图位**：每 800–1000 字一个配图位建议，标注"此处配图：XX 图"（示意图/截图/数据图），长段落后优先。
- **引用块**：他人原话或重要提醒用引用块，自文不用。
- **标点**：省略号、感叹号全文各至多一次；不用空行堆叠制造"呼吸感"。

## 输出

- 排版后的**完整全文**（小标题、分段、加粗、配图位标注就位）。
- 附 5 行以内的排版说明：判断的阅读场景、做了哪些结构手术、哪里建议用户补图。

## 边界

- 不改写观点、不增删事实、不动用户的原始表述风格；润色建议可以给，改动要用户点头。
- 标题与封面文案可另给建议，但不强行替换用户已定标题。
- 原文本身结构混乱时，先给结构诊断，再排版，不直接硬排。
