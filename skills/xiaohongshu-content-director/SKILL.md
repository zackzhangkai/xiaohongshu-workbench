# xiaohongshu-content-director：内容形态判断

动笔之前先回答一个问题：**这条内容靠什么被记住？** 这个技能就是那个"先想清楚"的环节。

## 判断链（按顺序走）

1. **读者是谁、在什么场景刷到**：通勤快速划、睡前慢刷、主动搜索——消费场景决定信息密度。
2. **记忆点是什么**：一个反常识结论、一套可直接抄的清单、一次真实改造、一段情绪共鸣。没有记忆点的内容，先补记忆点再谈形态。
3. **哪些素材必须被看见**：真实对比照片、步骤截图、数据图表、实物细节。必须被看见的素材决定图片形态。

## 形态菜单

- **单图强封面**：一句话结论 + 一张高信息封面图。适合观点、声明式内容。
- **实拍组图**：3–9 张真实照片按叙事排序（前后、过程、细节）。适合改造、探店、实测。
- **图文接力**：正文讲线，图片讲点，各承担一半信息。适合教程、攻略。
- **截图图解**：真实界面截图 + 标注说明。适合软件操作、账号复盘。
- **文字卡组**：信息密度高、无实拍素材时，做成编排卡片组。适合清单、知识整理。
- **视频建议**：过程性强、需示范的内容，输出视频脚本方向（本环境不产出视频成片）。

**选型底线**：最小充分——能用实拍不用制图，能用三张不用九张；但"必须被看见的素材"一张都不能省。

## 正文与图片分工

定形态后输出一张分工表：

| 内容点 | 承载方 | 说明 |
| --- | --- | --- |
| 核心结论 | 首图 + 正文首段 | 双入口，各说一遍但措辞不同 |
| 步骤/清单 | 图片 | 一张一点 |
| 细节与避坑 | 正文 | 图片留钩子，正文展开 |

## 输出与交接

- 用户**只要方案/初稿**：输出形态判断 + 分工表 + 首图创意，到此为止。
- 用户要**完整成品**（"写一篇小红书"默认即此）：判断完成后直接按 xiaohongshu-image-post 的流程继续生产，不把"方案"当交付。

## 边界

- 不因为"内容有知识点"就默认文字卡——先问有没有真实素材可用。
- 不替用户决定发布时间、账号策略；只管这一条内容的形态。
- 判断依据不足（没看过素材、不知道目标读者）时先问，不猜。
