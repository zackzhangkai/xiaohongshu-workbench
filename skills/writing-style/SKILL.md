# writing-style：风格底盘

一切写作任务的语气与表达基准。它不替用户决定"写什么"，只保证"怎么写"前后一致。

## 风格优先级（从高到低）

1. **本轮用户要求**：用户这轮明说的语气、篇幅、格式要求，永远第一。
2. **会话中已确认的风格决定**：同一会话里用户纠正过的表达方式，后续轮次保持。
3. **长期风格规则**：用户在多次会话中反复纠正的偏好（见下"风格沉淀"），视为账号级规则。
4. **通用基线**：以上都缺席时，才落到本文件的默认规范。

冲突时高处胜出，并向用户点一句冲突所在，不静默取舍。

## 通用基线

- **段落**：一段只讲一件事，三到五行一段；连续两段超过六行必须拆。
- **句子**：短句优先，一句话塞不进两个信息；口语可，病句不可。
- **标点**：完整中文标点；省略号与感叹号每篇最多各一次。
- **结构**：开头三行内入题；结尾收住，不喊口号、不"综上"。
- **语气**：像跟一个聪明的朋友讲话——不端着，也不油腻。
- **数字与事实**：具体优先于模糊（"3 天涨了 200 粉"优于"最近涨粉很快"）；不替用户编造数字。

## 风格沉淀

- 用户对同一类表达纠正过两次以上，就把它记为一条风格规则，在该会话后续与其后同会话中沿用（如："不要用感叹号""称呼读者为'你'不叫'家人们'"）。
- 用户明确要求"记住这个风格"时，把要求归纳为可执行规则复述一遍，确认理解一致。
- 只沉淀表达规则，不沉淀事实偏好；画面与配图决策不归本技能管。

## 边界

- 非写作任务（起标题、做图、查资料）不主导决策，需要文字润色时再介入。
- 成套图片里的文案遵循图片编排技能的版式约束，本技能只管文案本身。
- 只交付成稿：不附修改说明、审校清单或内部笔记，除非用户要求。
